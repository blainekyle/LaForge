1. Chronological Retrospective & Canonical Phase Roadmap

Reconciling the original 4-phase PRD with injected architectural sidequests (Phases 1 – 8)
Why Phase Numbering Evolved ("Phase 5" through "Phase 8"): At inception (Step 0), the PRD defined 4 foundational phases (PoC scripts → Native C# launcher.exe → APK Packager → Embedded scrcpy Bridge). 8. Defect & Regression Log (Root Cause Analysis & Resolution)

Tracked bugs from live user testing and their exact technical root causes
Tracker ID Reported Symptom Root Cause & Fix Applied Status
lmt-bug-15s-black-screen Music Player, Recorder & Cromite go black ~1.5s after interface appears Root Cause (Proven via adb logcat): LaForgeWindow.cs ran EnforcePoliciesOnGuest asynchronously in Task.Run after launching the app. When cmd appops set <pkg> MANAGE_EXTERNAL_STORAGE allow executed ~1.5s after launch, Android's ActivityManager logged Killing <pid>:<pkg>: MANAGE_EXTERNAL_STORAGE changed and destroyed the ActivityRecord.
Fix (v0.7.6): Pre-granted all runtime permissions + MANAGE_EXTERNAL_STORAGE allow in default_boot, moved EnforcePoliciesOnGuest before activity launch, and stopped touching MANAGE_EXTERNAL_STORAGE on running processes. 		● Validated
lmt-bug-phantom-bg-on-close Console shows closed apps as BACKGROUND & closing a window moves it to BACKGROUND Root Cause: (1) QueryLiveTelemetry treated any cached Linux process (pidof > 0) as IsBackgrounded and scanned into Recent tasks: in dumpsys activity activities. (2) Closing a window when background_on_close=false didn't run am force-stop.
Fix (v0.7.6): IsBackgrounded now requires an active non-finishing ActivityRecord or active audio stream, and closing a window with background_on_close=false runs am force-stop. 		● Validated
lmt-bug-mic-silence Voice Recorder generates silent audio files from host microphone Root Cause: Program.BuildEmulatorArgs passed -no-audio and omitted -allow-host-audio (which QEMU's help documents as: "Allows sending of audio from audio input devices. Otherwise, zeroes out audio.").
Fix (v0.7.6): Live emulator launches now pass -allow-host-audio with adb emu avd hostmicon and pre-granted RECORD_AUDIO. 		● Validated
lmt-bug-gallery-camera-same-window Invoking Camera from Gallery loads Fossify Camera inside Gallery's window & causes window resize Root Cause: Android launches chooser intents on the caller's virtual display (Display #2), and Fossify Camera requests screenOrientation="portrait", causing Android to rotate Display #2 (1280x720 → 720x1280) and scrcpy to resize the caller window before breakout.
Fix (v0.7.6 → v0.7.7): BindAppToVirtualDisplay now locks per-display rotation (wm set-ignore-orientation-request -d <id> true), CheckCrossAppBreakoutAsync polls every 750ms, and TryRestoreWindowBoundsByPid pins the caller window's exact Win32 RECT. 		● Validated
lmt-bug-camera-validator Fossify Camera displays "Accessing camera failed" & "Switching camera failed" Root Cause (Proven via adb logcat): AVD config.ini had hw.camera.front = none (or bound the same physical webcamN handle to both Rear and Front simultaneously, causing QEMU's webcam service to drop the Front camera). When Fossify Camera initialized AndroidX CameraX, CameraValidator threw CameraIdListIncorrectException: Expected camera missing from device.
Fix (v0.7.7 & v1.0.0): Enforced distinct physical webcam binding in LaForgeMasterSettings.cs (Rear=emulated, Front=webcam4) and added automatic emulator camera HAL reinitialization + default_boot snapshot resave when saving Master Settings. 		● Validated
lmt-bug-camera-pillarbox-window Fossify Camera spawns with landscape gray band / black bars on default launch Root Cause (Proven via dumpsys window displays & display_settings.xml): Even after setting 544x960 in v0.7.8, /data/system/display_settings.xml inside the default_boot snapshot contained a persisted forcedWidth="1600" forcedHeight="904" entry for virtual:com.android.shell,2000,scrcpy,0 (Display #48), overriding the first virtual display from init=544x960 to base=1600x904! Additionally, wm fixed-to-user-rotation enabled activated Android 14's LetterboxUiController (Rect(545, 0 - 1056, 904)).
Fix (v0.7.11): Purged /data/system/display_settings.xml and saved a clean default_boot snapshot (init=544x960 cur=544x960 app=544x960), set wm fixed-to-user-rotation disabled (while keeping wm user-rotation lock 0 + wm set-ignore-orientation-request true), and enabled dynamic_aspect_resize=true by default. 		● Validated
lmt-bug-newly-forged-gray-screen Newly forged APK launches to an empty gray virtual display window Root Cause: (1) SideloadAndGrantPermissions checked pm list packages <pkg> (which matches substrings and didn't verify pm path) and ran after scrcpy virtual display creation; (2) RunProcessCaptureOutput discarded stderr (Error type 3: Activity class ... does not exist) whenever stdout was non-empty; (3) StopHeadlessEmulator killed QEMU after only 800ms, leaving read-snapshot.txt and invalidating default_boot.
Fix (v0.9.2): Added Program.IsPackageInstalled (pm path), moved SideloadAndGrantPermissions before scrcpy virtual display allocation, combined stdout+stderr, increased graceful QEMU shutdown wait to 5000ms + CleanStaleAvdLocks, and saved a fresh default_boot snapshot. 		● Validated
